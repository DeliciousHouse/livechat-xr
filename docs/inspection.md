# Sanitized cache inspector (F1)

This is a read-only view of the existing sanctioned cache, not a live collector or public-network activation. Source review/CI and Dora's fresh external inspection are separate acceptance steps. A populated lawful/fresh production cohort, E6, Google acceptance and upload capability remain unproved. Q owns those dispositions.

## Source and trust boundary

`Store.inspection_rows()` calls existing `discovery()` / `live_channels()` filtering, with additional conservative observation validation. `Projection` uses the existing `render_live`, `go_link`, `resolve_go` and `safe_destination`; it never calls `Network.start()`. The owning application alone reads its existing Store, read-only, under its Store lock. The viewer has no database, runtime environment file, registration/OAuth/admin routes, provider client, or visitor log. No schema migration, new dependency, polling/search or credential is required.

The existing application can opt into `configured_runtime()` with an exact `INSPECTION_REVISION` and either `INSPECTION_SOCKET` (recommended for Dora's bridged container) or `INSPECTION_PORT` (same network namespace only). This is the minimal reviewed runtime-local exporter installation. It does not enable Network, add provider work, or change existing holds. A bind/configuration error disables only inspection and logs its exception type, not private values. Do not start a second relay/collector to obtain a projection.

The Docker image includes the new module. A port bound to `127.0.0.1` inside a bridged relay container is NOT host loopback. Do not publish it or mount the raw data volume into the viewer. Instead set `INSPECTION_SOCKET=/data/inspection/projection.sock` in the existing application's launch environment through Dora's normal controller, preserving all other runtime flags, image rollback and continuity checks. Only the `inspection` directory, containing the sanitized socket, may cross the boundary. Mount the directory, not one socket inode, so a sanctioned exporter replacement is visible. The viewer must not receive its parent data directory. The socket is mode 0666 because it serves only the allowlisted public projection and rejects writes; its directory remains application-owned. Stale sockets are not automatically replaced: after independently verifying the old exporter is stopped, Dora may remove only that socket and restart the inspection hook. Never remove a cache/database.

## Version 1 input contract

UTF-8 JSON, maximum 262144 bytes. Exact top-level keys (additional keys are rejected):

- `schema`: integer `1`.
- `source_revision`: exact lowercase 40-hex source commit supplied by the trusted runtime.
- `source_digest`: SHA256 over named, LF-normalized source bytes, generated by `python server/inspection.py digest`. Names/order are `inspection.py`, `network.py`, `backup.py`, `chat.py`, `server.py`; each name and content are NUL-separated. Viewer independently verifies its own installed bytes and pins the same revision/digest on every input.
- `generated_at`: actual UTC generation time, canonical `YYYY-MM-DDTHH:MM:SS.ffffffZ`. It is not observation time. Reject future timestamps or age of 15 seconds or more.
- `eligibility`: fixed versioned description of the Store filter (verified, opted-in, reviewed, primary Population: ONE count 0–10, observation under 1800 seconds).
- `availability`: `available`, `observed-empty`, or `unavailable`.
- `eligible_count`, `unknown_primary_count`: bounded aggregate counts; null when unavailable. An unknown count is never substituted with zero.
- `polls`: exactly `twitch` and `youtube` keys (the current `network.INTERVALS`; no TikTok discovery poll), each the actual runtime last-success UTC timestamp or null. Missing/future/stale poll provenance cannot establish observed-empty. No filesystem mtime or process-start substitution.
- `rows`: at most 100 eligible presentations and 200 source channels total. Each row has only `name`, `channels`. Each channel has only `platform`, `viewers`, `observed_at`, `seen_at`, `destination`. `name` is the public IGN or primary handle (1–128 characters); there are no separate row-level count/observation or channel display fields. `platform` is `twitch` or `youtube`; `viewers` is a nonnegative integer or null for an unknown secondary audience. Channel timestamps are finite positive Unix seconds (not the UTC strings used by `generated_at` and `polls`), no later than generation: `seen_at` is presence freshness, under 1800 seconds; `observed_at` is channel observation freshness, under 86400 seconds. No creator/Discord/user IDs, preferences, credentials or unapproved details are exported.
- `text`: bounded real renderer presentation (plain text, HTML-escaped by the viewer).
- `watches`: at most 200 opaque 22-character URL-safe tokens mapped only to the exact allowlisted destinations present in current rows. Strict source hosts/path checks remain in force; no arbitrary redirect URL.

An unavailable/invalid/missing/capacity-exceeded input produces HTTP 503 and no Watch authority. Observed-empty is HTTP 200 only after readable cache plus actual complete successful recent poll provenance and no unresolved primary observations. It does not certify a populated cohort. Available rows retain unknown secondary counts and original observation timestamps. A stale row in an otherwise syntactically valid packet fails the packet closed.

Every viewer GET obtains a fresh complete projection; no viewer projection cache, file-based refresh race, or persistent visitor analytics. Generation is serialized and read under the owning Store lock. GET `/go/<token>` obtains a NEW projection, checks revision/digest/freshness, and looks up that token and strict destination again. Withdrawal, eligibility/handle change, removal, upstream loss and expiry therefore fail closed on the next request. An already displayed page cannot retract an already-followed external link. File replay never authorizes redirects and is labelled replay, never live.

## Runnable commands (Dora-owned operations)

Use the exact reviewed source checkout/bundle with existing pinned dependencies. Substitute the reviewed revision, artifact digest and installation prefix from the immutable receipt. No command needs a provider key. Do not print or copy a runtime env file.

```sh
REVISION=b083eccae7aaa9b2aaa0017c47ccc99ff6a1d756
DIGEST=33f61ecc92c0f0f6100e451ec3e69b9a30e50b41fe69388356bbd3040b684e89
python server/inspection.py digest

# One-shot sanitized export; application-owned command, ONLY existing sanctioned cache.
# This does not initialize a cache, migrate, poll or infer another runtime's poll times.
: "${EXISTING_APPLICATION_CACHE_DIRECTORY:?existing sanctioned application cache required}"
DATA_DIR="$EXISTING_APPLICATION_CACHE_DIRECTORY" python server/inspection.py export --revision "$REVISION" > sanitized.json

# Inspection-only replay; no Watch authority, original observations retained.
python server/inspection.py viewer --revision "$REVISION" --digest "$DIGEST" --input sanitized.json --port 8787

# Preferred continuous input: fixed SANITIZED socket, never raw DB.
python server/inspection.py viewer --revision "$REVISION" --digest "$DIGEST" --socket /run/livechat-inspection/projection.sock --port 8787

# Alternative only when exporter and viewer already share a network namespace:
# Existing runtime: INSPECTION_PORT=8788 and INSPECTION_REVISION=$REVISION.
python server/inspection.py viewer --revision "$REVISION" --digest "$DIGEST" --upstream-port 8788 --port 8787
```

A one-shot export cannot recover in-memory poll receipts from another process: missing receipts remain null/unavailable. Never present it as an observed-empty production export. A replay older than 15 seconds is unavailable. Continuous inspection uses the existing runtime hook, not repeated CLI cache reads or a second polling service.

Both TCP listeners hard-bind `127.0.0.1`; no bind-address/URL/DB/query option exists. 8787 and optional 8788 are candidate ports, not reservations. Dora must inspect actual listeners/process identity first. IPC input is fixed at process startup and only GET `/projection`; the source endpoint is never a public proxy target. The viewer needs no environment inherited from the relay. Use a nonprivileged, clean-environment sandbox with read-only reviewed code and only the sanitized IPC directory. On Linux an appropriate existing systemd transient-process sandbox can additionally enforce `IPAddressDeny=any`, `IPAddressAllow=localhost`, `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, inaccessible raw-volume/runtime-env paths, and a read-only bind of the sanitized directory. Dora must verify the actual host supports/enforces those settings; these are not an executed host receipt. Application tests deny provider calls; they do not certify kernel egress policy. Do not grant the viewer Docker control or relay credentials. Do not put it in the relay's raw-volume container.

Example isolated HOST process after Dora stages reviewed code/dependencies at `/opt/livechat-inspection` and resolves only the sanitized socket directory as `$IPC_DIR` (no raw-volume mount/copy):

```sh
sudo systemd-run --unit=livechat-xr-inspector --collect --uid=nobody \
  --property=WorkingDirectory=/opt/livechat-inspection \
  --property=NoNewPrivileges=yes --property=ProtectSystem=strict --property=ProtectHome=yes \
  --property=IPAddressDeny=any --property=IPAddressAllow=localhost \
  --property=InaccessiblePaths=/var/lib/docker \
  --property="BindReadOnlyPaths=$IPC_DIR:/run/livechat-inspection" \
  /usr/bin/env -i PATH=/usr/bin:/bin HOME=/nonexistent LANG=C.UTF-8 \
  /opt/livechat-inspection/.venv/bin/python server/inspection.py viewer \
  --socket /run/livechat-inspection/projection.sock --port 8787 \
  --revision "$REVISION" --digest "$DIGEST"
```

The host launch example is a contract for Dora to execute/verify, not a claim that `/opt`, sudo, systemd/BPF restrictions, mounts or the ports have been provisioned. If Dora instead uses its existing sandbox, it must provide the same credential/filesystem/provider-denial and loopback guarantees without adding a raw-DB mount. No owner intervention is requested. A normal viewer starts/stops independently of the relay.

## Exact proxy contract for Q / Dora E

Upstream: verified HOST `127.0.0.1:8787`, never the relay 13300 port and never the exporter. GET only; query string must be empty; reject request bodies/transfer encoding. Allow exactly `/live` and `/go/[A-Za-z0-9_-]{22}`. Reject encoded path aliases, trailing slash, `/`, `/projection`, `/admin`, `/oauth`, registration, messaging, static/file/source paths and every other path/method. No catch-all, caching, rewriting, fallback-to-relay, or visitor logging. No external fonts/scripts/images are required. The application repeats path/method/size/destination checks even behind the proxy.

Viewer responses carry `Cache-Control: no-store, max-age=0`, but no source-revision, digest or availability response headers. `/live` displays the pinned source revision and artifact digest in its footer, including when unavailable. For available/observed-empty input it also displays generation, actual poll receipts and original channel observations. Availability is conveyed by HTTP status and page content, not a response header. The exact eligibility semantics are validated in the sanitized projection's `eligibility` field; the page describes Watch revalidation but does not display that fixed filter string. Keep unavailable HTTP 503 visible; do not rewrite it into a successful empty page. External source links remain branded provider links, not embedding or scraping. Watch redirects use HTTP 303 only after current projection revalidation. Well-formed but unknown tokens fail with HTTP 410, as do withdrawn/stale/unavailable targets and file-replay Watch requests. Malformed token paths and other disallowed routes fail with HTTP 404.

Dora owns installation/listener verification and source-backed cache access. Q's existing controller owns the Caddy LXC route (Dora has no Caddy key). Canonical review/required exact-head CI must precede host activation; after merge rebind revision to the actual installed reviewed commit and recompute/verify source digest. Any code-byte change invalidates this packet. No F1/O6/terms/security/public-activation hold is lifted by this route.
